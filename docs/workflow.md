# ワークフロー

HTML/CSS で描く → ヘッドレス Chromium でパーツを透過 PNG に書き出す → Affinity で統合する → 画素で検証する、という流れ。各段階の判断基準を書く。

## 1. どこまで HTML で作り、どこから Affinity でやるか

| HTML/CSS 向き | Affinity 向き |
|---|---|
| グラデーション、ぼかし、Web フォント、角丸、影、格子などの背景パターン | 配置の微調整、線・矢印、編集可能なテキスト、レイヤーエフェクト |
| 色や文言をあとで差し替える可能性が高いもの (変数化しておく) | 手でドラッグして詰めたいもの |

理由: CSS は再現性と再編集性が高く、変数の差し替えだけで案を量産できる。Affinity は最終の統合と、後から人が触る部分に使う。

## 2. 案出し

- 決める順番を固定する (例: 構図 → 配色 → 背景 → 光 → マーク → 書体)。決まったものは固定して次を振る。
- 色・光・格子の濃さは `:root` の CSS 変数に寄せ、案ごとの変数値を JSON に残す。
- 案は必ず現在の構図の上に描画し、1 ページのギャラリー (HTML アーティファクト) で比較する。
- 参考にする既存物は実物を取得して寸法と構成を測る。読み取るのは「文法」(線か塗りか、器の有無、色数、プリミティブか構築か)。否定されたら個別案ではなく文法を変える。

## 3. パーツ書き出し

- 最終構図の HTML を原本にし、パーツごとに他要素を `visibility:hidden` にしたレイヤー HTML を同じキャンバスサイズで描画する。
- `html,body{margin:0;padding:0}` を必ず入れる (既定 margin 8px で全パーツがずれる)。
- 端に近い要素はキャンバスより広い幅で描画してから切り出す (グロー切れ防止)。
- `magick -trim` で切り出し、切り出しオフセットと本体境界 (`measure.sh body`) を記録する。

## 4. Affinity での統合

- ドキュメントは pixel 単位・`isLandscape` 明示で作る。
- ラスターを下から順に置き、線・バッジ・テキストを上に置く。新規ノードは一意な説明文で特定する。
- 線は要素本体の中心から出す。合流線は「合流点 → 短い直線 → 先端」の直交配線が読みやすく、曲がり角だけ丸める。合流点は T 字で 3 本を同じ点に接続する。
- 要素の高さが違う 3 段を上下対称にするには、中央要素の中心から上下の中心が等距離になるよう間隔で調整する。「間隔統一」と「対称」は両立しないので、どちらを優先するか明示する。

## 5. 検証と報告

- 変更のたびに PNG を書き出し、拡大切り出しで接続部・端を見る。
- 余白は座標ではなく可視範囲 (グロー込み) を画素で測って揃える。CSS の `width` は content-box なので実寸を測り直す。
- 報告には測った数値 (余白、中心 y、隙間) を添え、変えた点・変えなかった点・トレードオフを短く書く。本画像はファイルとして送る。
- 指示にない変更 (幅、サイズ、内容) はしない。必要なら提案に留める。
